# Training Readiness design

## Purpose and scope

Readylytics retains its existing **Readiness** score unchanged and adds a second, independently
visible score named **Training Readiness**. It incorporates the existing workout-only Residual
Fatigue model without changing that model, canonical workout TRIMP, Load Score, sleep scoring,
or Training Advisor recommendations.

Training Readiness is an opt-in, default-hidden Dashboard metric. It is intentionally not added
to Workouts cards, trends, insights, history/detail screens, widgets, or Advisor inputs in this
release.

## Formula and score semantics

With raw residual fatigue `F`, residual-fatigue scale `S`, load-balance weight `w`, and the
source-matched existing Load Score `L`:

```
AcuteLoadRecovery = clamp(100 * exp(-F / S), 0, 100)
TrainingLoadReadiness = clamp(w * L + (1 - w) * AcuteLoadRecovery, 0, 100)
TrainingReadiness = existingReadinessCalculator(Restoration, Sleep, TrainingLoadReadiness, flags)
```

`existingReadinessCalculator` is the established calculation that applies the normal score bounds
and illness-onset cap. This preserves the legacy safety ordering without introducing a second
fatigue cap. `w = 1` is mathematically equivalent to Readiness within floating-point tolerance.

Residual Fatigue remains raw, nullable, unbounded, canonical-workout-only, and independent of
`LoadSourceMode`; Everyday-HR TRIMP never enters it. If it is unavailable, Acute Load Recovery is
also unavailable (never 100), Training Load Readiness equals the source-matched Load Score, and
Training Readiness equals the corresponding existing Readiness. If normal Readiness is unavailable
because calibration or recovery inputs are unavailable, Training Readiness is unavailable too.

Defaults and valid ranges are provisional product parameters:

| Parameter | Default | Range / input |
| --- | ---: | --- |
| Residual fatigue scale `S` | 100 | 75–175; slider step 5 |
| Load balance weight `w` | 90% | 80–100%; slider step 1% |

## Persistence and applied configuration

Daily summaries persist `acuteLoadRecovery`, source-specific
`trainingLoadReadinessWorkoutOnly` / `trainingLoadReadinessEverydayHr`, and
`trainingReadinessWorkoutOnly` / `trainingReadinessEverydayHr`. Persisting the projection is
necessary: it preserves the score generated by the last applied parameters and prevents merely
editing settings from rewriting history at display time.

Preferences retain two editable parameters and two last-successfully-applied parameters. Existing
daily and full scoring passes use the applied values, not pending edits. A user change therefore
does not alter the shown score until they explicitly request recalculation.

The old residual-fatigue enable preference is removed from the domain model and behavior. Its
protobuf field number and name remain reserved/unknown for binary compatibility, so a historical
`enabled=false` cannot disable the model. The residual-fatigue half-life and gain preferences stay
available and always govern the existing fatigue model.

## Calculation paths

The existing daily scoring path continues to calculate legacy Readiness first. The final summary
assembly calculates/reuses the nullable residual-fatigue snapshot and applies a pure Training
Readiness projector with the applied configuration. This adds no data fetch, HR processing, or
second fatigue accumulator.

An explicit "Recalculate Training Readiness" action uses the existing unique resync worker and
progress channel but selects a projection-only work mode. Its WorkManager input carries the exact
scale and weight requested. The worker pages retained daily summaries, projects from persisted
inputs, and rewrites only the Training Readiness columns. It has no Health Connect, raw HR,
TRIMP, or residual-fatigue reconstruction work. It is idempotent; cancellation/failure does not
mark values applied, and a retry with the same input converges. If settings are edited while the
worker runs, the completed input becomes the applied value and the differing current settings keep
the action enabled.

Initial rollout increments the scoring version. Startup schedules the existing recompute-only
historical worker, which fills these columns from defaults; it also records the default applied
configuration only after success. This migration is distinct from later user parameter edits,
which require the explicit action.

## UI and documentation

Advanced Settings removes the residual-fatigue enable switch and adds a Training Readiness section
with two Material 3 sliders, directional supporting text, reset-to-defaults, and an explicit
recalculate button. The button is disabled when editable and applied values match or background
work is active.

Dashboard card layout gains `TRAINING_READINESS`, default hidden, with the existing score-card
display modes and statuses. It uses the selected strain/load source for the Load Score branch and
the shared workout-only fatigue branch. Existing Readiness stays visible and unchanged.

The score-formula/data-flow documentation is updated together: `ABOUT.md`, `docs/about.md`,
`internal-docs/DATA_FLOW.md`, and in-app About/tooltip/settings resources. The public explanation
states the two scores' distinction, parameter defaults/ranges, missing-data fallback, workout-only
fatigue provenance, and unchanged Advisor behavior.

## Migration and verification requirements

Room moves from v16 to v17 by adding nullable daily-summary projection columns; backup streams
already serialize `DailySummaryEntity`, and preference backup/restore gains editable/applied
parameter fields. Tests cover Room/protobuf/backup migration, old enable=false compatibility,
default startup backfill, process restart, projection-only idempotence, and no new raw-data reads.

Pure-Kotlin formula tests cover zero and monotonic fatigue behavior, scale monotonicity, symmetric
blending (including recovery above Load Score), source variants, missing fatigue fallback, bounds,
and equivalence at weight 1. Integration/determinism tests cover daily sync, full resync,
backfill, partial recompute, restart, ingestion order, and LoadSourceMode changes while asserting
all legacy scoring and Advisor outputs remain unchanged.
